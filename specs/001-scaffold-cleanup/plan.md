## Approach & Sequencing

**Why this order.** US1 and US2 are pure deletions with no ripple — safe first. US3 is
the only story that can break the build (the `[lib] name` / `main.rs` pair must change
together), so it is isolated in its own phase with its own gate run. US4 is text-only
and last.

**Story independence.** Every story stands alone and is separately revertable. US1 and
US3 both edit `package.json` and `src-tauri/Cargo.toml`, so they must not run in
parallel *with each other* — this is the only cross-story file conflict in the feature.
US2 and US4 touch disjoint files and can run in parallel with anything.

**Lockfiles.** Both are regenerated inside US1 rather than deferred to polish, so the
story leaves the tree in a self-consistent state.

**Tests.** No new tests. The spec asks for none, the constitution's testable-core rule
is unaffected (no logic changes), and writing tests that assert on cosmetic metadata
would pin the wrong thing. The existing 41 tests plus clippy are the gate.
