## Summary

Getting from a row to the page it watches took five actions — select the URL, copy it, switch to a browser, paste, return. It now takes one: each site's URL is a control that opens that address in the OS default browser, by click or by Enter, without the dashboard itself ever navigating.

The feature is small in surface and deliberate in its edges. Only `http` and `https` are ever opened, the guard runs before anything is spawned, and — after two defects QA found and closed — what the UI offers as clickable is exactly what the backend will actually open.

## Known issues

Nothing here blocks merge. All are the review's 🟢 suggestions or named environment gaps.

**Open — carried forward as-is:**

- **R003 — a failed activation cannot be retried for 1000 ms.** `shouldOpen` records the activation *before* the command is attempted, so a user who clicks, reads the banner, and immediately clicks again gets silence. Deliberately left: FR-012 is a SHOULD and the failure path is rare. The trade is that clearing the ledger on failure would make a failing address re-openable on every click of a drum-roll.
- **R004 — `#[tauri::command(async)]` on a synchronous body** blocks an async-runtime worker for as long as `open` takes to return. Negligible at this app's scale (one user, one Mac, a 1000 ms client throttle); recorded so the choice is visible rather than assumed. `spawn_blocking` is the fix if it ever matters. **No action recommended.**
- **R005 — no `aria-label` on the control.** A screen-reader user hears `"https://example.com, button"` with nothing indicating that activating it leaves the app. This is the second-order cost of the `<button>`-over-`<a href>` decision, and it was not recorded in the plan at the time.
- **R006 — no unit test asserts `document.activeElement` across a repaint.** QA exercised real `Tab`, real `Enter` and focus survival across two repaints in a real engine (TC-310, TC-311), so the behaviour is *verified*; it is the automated regression guard that is missing. The +3 tests added by the fix pass were all for `isOpenable`.

**Environment gaps — could not be exercised on this machine:**

- **SC-003's visible half is unverified.** `/usr/bin/open <https url>` returned exit 0 in **33/48/62/67 ms** — ~30× inside the two-second budget — and genuinely spawned browser content processes. But whether the browser actually *comes forward on screen* could not be observed: the frontmost app stayed `Terminal` at 0.5/1.2/1.9/2.6 s, and it could not be determined whether that is this machine's URL router (Finicky) declining to steal focus or macOS focus-stealing prevention. **Accessibility and Screen Recording were both refused** to this run (`AXIsProcessTrusted()` false even from a compiled Swift binary; `screencapture -R`/`-l` fail outright). Confirming this needs a session with both permissions granted, or a human watching one click.
- **WKWebView was never the engine under test.** All browser-driven QA and all `after/` screenshots ran the shipped frontend modules in **Chromium** via the project's own Vite dev server. This is not academic — see the `%`-encoding note below, where Chromium and happy-dom disagreed about the same input and the app ships in neither.

**Closed — recorded because they shaped the design:**

- **R001 / TC-104** — `openable_url` validated `trimmed` but returned `input`, so a whitespace-padded stored address passed both guards and reached `/usr/bin/open` still padded. macOS resolves a leading-space argument as a **file path**, not a URL, so the address could never open and the banner named a filesystem path the user had never seen. Fixed: the guard returns the trimmed address, so what is validated is what is opened.
- **R002 / TC-213** — `isOpenable`'s `^https?://` prefix test was strictly more permissive than the backend guard, so `https://`, `http://`, `https://[bad` and `https://exa mple.com` were all rendered as underlined controls the backend then refused. Fixed: the frontend now requires a parseable, non-empty host free of `%` and whitespace.
  > Worth reading the QA report on this one. The *first* attempt at the fix (`new URL(trimmed).host !== ""`) went green in `pnpm test` while the real browser still rendered a dead control — happy-dom **throws** on `https://exa mple.com`, whereas Chromium's forgiving parser percent-encodes it to `exa%20mple.com` and reports success. Deciding the `%`/whitespace question *inside* the guard makes the answer identical in every engine, which matters because the app ships in WKWebView — neither engine it is tested in. A legitimate space in a *path* (`https://example.com/a b`) still opens.

## Open decisions awaiting your confirmation

No user was present for this run. **Eight** decisions were taken without one. All eight are recorded at the point they were made; none is load-bearing enough to block merge, but each is a genuine fork.

From [spec.md](https://github.com/clintcparker/site-checker/blob/2253ab851580e9f28d4598a032ad16f6e9ab6e69/specs/20260813-105424-urls-clickable-and/spec.md#open-decisions-for-review):

1. **Only the URL text is activatable** — not the whole site cell, not the label. A whole-cell target is easier to hit but blurs what is being opened and crowds the row actions.
2. **No new column or icon.** The URL is styled to read as activatable in place, rather than gaining an external-link glyph or an "Open" button beside Edit and Delete.
3. **Non-http/https entries are shown but inert** — rendered as plain text rather than hidden, flagged, or repaired on load.

From [plan.md](https://github.com/clintcparker/site-checker/blob/2253ab851580e9f28d4598a032ad16f6e9ab6e69/specs/20260813-105424-urls-clickable-and/plan.md#open-decisions-for-review):

4. **A first-party command over `tauri-plugin-opener`.** The plugin was removed from this repo in `522367e` as scaffold residue (−368 lines of `Cargo.lock`, largely a Linux DBus stack this macOS-only app cannot use), and its scope allowlist would have to be `http://*` + `https://*` anyway, adding no guard FR-007 does not already provide. Revisit if the app targets a second platform.
5. **A `<button>`, not an `<a href>`.** An anchor is more semantic and gets keyboard activation free, but carries a URL the webview can follow on middle-click (`auxclick`), Cmd-click, or any path where the JS handler did not run — and FR-003 calls that unrecoverable. Cost: AT announces "button", not "link" (see R005).
6. **The frontend repeats the scheme guard** rather than asking the backend, because FR-007's second sentence is a *rendering* decision made ~60×/minute and cannot be an IPC round-trip. Recorded as known duplication rather than hidden. **R002 is the finding that may reopen this one.**
7. **A 1000 ms per-URL suppression window**, chosen over disabling the control while the command is in flight — the command resolves as soon as LaunchServices accepts the address, long before the browser is forward, so an in-flight guard would close a window of effectively zero width.
8. **The name cell is rebuilt on a label add/remove**, since that transition moves the URL between the primary and secondary slot. Does not weaken FR-011: a label change is a user edit, not a repaint.
