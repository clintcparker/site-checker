## Executive Summary

This is a well-built, well-argued feature. Every non-obvious choice — a
first-party command over `tauri-plugin-opener`, a `<button>` over an `<a href>`,
a duplicated scheme guard, a 1000 ms activation window, a rebuild of the name
cell on a label flip — is written down at the point it is made and is
traceable back to a requirement. The security-relevant surface (handing a
user-controlled string to a process) is handled properly: absolute binary path,
no shell, single argument, scheme allowlist applied before anything is spawned,
`javascript:` and `file:///` explicitly refused and tested. FR-010's isolation
from the row's Edit/Delete handler is structural (`data-open-url` vs
`data-action`) rather than conventional, and FR-011's focus survival is
protected by the same in-place reconciliation the rest of `render.ts` already
kept, with tests asserting element identity across a repaint. All quality gates
are green: `cargo test` 100 passed, `pnpm test` 77 passed, `cargo clippy
--all-targets -- -D warnings` clean, `tsc --noEmit` clean. All 27 tasks are
checked off.

Two findings hold it back from a clean approval, both confirmed empirically and
both confined to the same narrow entry point the feature was already designed
around — a `sites.json` edited by hand. Neither is a security problem and
neither can crash, corrupt, or hang the app; both fail safe into the banner. But
both are cases where the UI offers an address as activatable and the backend
then refuses it, which is exactly what FR-007's second sentence forbids. The
more interesting of the two (R001) is a genuine bug rather than a judgement
call: a stored address with surrounding whitespace passes both guards, is
handed to `/usr/bin/open` with the whitespace intact, and `open` then resolves
it as a *file path* rather than a URL — verified below.

### Security Assessment

No security findings. The one privileged act — handing a user-controlled string
to a process — is done correctly:

- **No shell.** `std::process::Command::new` with a single `.arg()`; no `sh -c`, no string interpolation into a command line. Command injection is not reachable.
- **Absolute binary path.** `/usr/bin/open`, so which binary runs cannot be steered by an inherited `PATH`.
- **Argument injection not reachable.** The guard admits only http/https, and even in the R001 padded case the argument begins with whitespace, never `-`.
- **Scheme allowlist applied before anything is spawned.** `javascript:`, `file:///`, and `ftp:` are refused with an explicit test each — these are the schemes a hand-edited `sites.json` would be attacked with, and they are the ones the feature was written to stop.
- **No injection into the DOM.** `textContent` and `dataset` only; no `innerHTML` anywhere in the new code.
- **No new capability grant.** `src-tauri/capabilities/default.json` is unchanged — the first-party-command route needs no permission entry, which is precisely what avoiding `tauri-plugin-opener` bought.
- **No secrets, no logging of sensitive data.** Error messages name the user's own URL inside the user's own app.
