## Implementation

**US1 — startup event window.** Both `listen` registrations moved above every other `await`
in `main()`. The new order lets a status arrive for an id `sites` does not hold yet; that is
benign, because `currentRows()` iterates `sites`, not `statuses`, so it renders as soon as
`listSites()` resolves. Both handlers close over module-level bindings that exist before
`main()` is called.

**US2 — stale status on URL change.** `upsertSite` now drops the status when — and only
when — the URL changed. Label-only and interval-only edits keep the dot, because that result
is still about that URL. Both sides of the comparison are backend-normalized (`addSite`/
`updateSite` resolve to the saved `Site` after `normalize_url`), so a cosmetic difference the
backend already collapsed cannot false-positive into a spurious reset.

**US3 — in-flight guards.** Submit and per-row Delete disable their button around the awaited
call and return early if it is already disabled. The explicit `disabled` check matters
because the handler also runs for a programmatic submit, which never consults `disabled`.
Submit re-enables in a `finally` so a rejected save stays retryable; Delete re-enables only
on the failure path, since on success `onDeleted` removes the row and its button with it.

**US4 — interval ceiling.** `max="86400"` in `index.html` plus a matching `Math.min` in the
clamp. The form is `novalidate`, so the attribute shapes the spinner rather than blocking a
paste — the clamp is what a pasted value actually meets. 86400 is a product guardrail chosen
here, not a protocol limit; the backend still enforces only `MIN_INTERVAL_SECS`.

**US5 — autostart null guard.** Early-return with a banner instead of `querySelector(...)!`,
which leaves the `catch` block operating on a checkbox known to exist.

## Testing

- **`src/form.test.ts`** — DOM unit tests over `form.ts` in `render.test.ts`'s local-fixture
  style, with `./api` stubbed by deferred promises so the in-flight window is inspectable.

## Known limitations

- **The GUI walkthroughs in T011 and T019 were not performed by hand.** Both Independent

  neither unit test exercises the real IPC round trip. (The later screenshot session *did*

  case or T019's paste case.)

  `index.html`'s `max` attribute, and the ceiling case in `form.test.ts`. The constant's
