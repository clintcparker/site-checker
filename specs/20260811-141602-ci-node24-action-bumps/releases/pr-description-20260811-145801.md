## Summary

Every JS action pinned in `ci.yml` and `release.yml` sat on a major whose `runs.using` is `node20`,
so both workflows emitted a Node 20 deprecation annotation on every otherwise-green run — the
failure mode where nothing breaks and nobody looks. This bumps all 14 `uses:` lines across six
distinct actions to majors that run on `node24`, adds `.github/dependabot.yml` so the next runtime
deprecation arrives as a reviewable PR instead of an annotation, and records the resulting Actions
runner floor of ≥ 2.327.1 in `docs/how-to/release.md`.

Nothing user-visible. `git diff -- src index.html src-tauri` is empty.

| Action | Before | After | Why not higher |
|---|---|---|---|
| `actions/checkout` | `v4` | `v5` | v6/v7 change credential-persistence defaults; v5 is the first `node24` major |
| `actions/setup-node` | `v4` | `v6` | v5 is already `node24`; v6 narrows auto-caching to npm only, and all three call sites pass `cache: pnpm` explicitly, so the narrowing is never consulted. v7 declined |
| `pnpm/action-setup` | `v4` | `v6` | v5 is already `node24`; v6 adds pnpm 11 and still self-updates to the `packageManager` version `package.json` pins. No v7 exists |
| `actions/upload-artifact` | `v4` | `v6` | v5 is still `node20`; v7 switches to direct upload |
| `actions/download-artifact` | `v4` | `v7` | v6 is still `node20`. **v8 defaults `digest-mismatch: error`** — accepting it turns a logged warning into a failed release run — and v8 also skips decompression, which would break the `release` job's globs |
| `softprops/action-gh-release` | `v2` | `v3` | No v4 exists. v3 still defaults `overwrite_files: true`, preserving the "re-run converges on one release object" property the file's comment promises |

`Swatinem/rust-cache@v2` is already `node24` and `dtolnay/rust-toolchain@stable` is a composite
action; both were deliberately left untouched. `verify-install-channels.yml` has zero `uses:` lines
and is not in this diff.

### Blocker D1 — raised at 14:58, fixed in `4adc898`, verified closed at 15:03

**As raised: the `ignore:` block in `.github/dependabot.yml` defeated User Story 3 for four of the
six actions this feature bumps.** Each entry declined
`update-types: ["version-update:semver-major"]` for `actions/checkout`, `actions/setup-node`,
`actions/upload-artifact`, and `actions/download-artifact`. All four are referenced in the workflows
by a bare major tag (`@v5`, `@v6`, `@v6`, `@v7`), and for a major-tag reference the *only*
version update Dependabot can propose is a major bump. So the decline is not narrow — it is total.
Dependabot will never open a version-update PR for those four actions again.

That reinstates the exact failure this feature exists to prevent, for 11 of the 14 bumped `uses:`
lines including every action on `release.yml`'s artifact path: when GitHub retires Node 24 the way
it retired Node 20, the successor major is ignored, nothing is proposed, and the deprecation arrives
as an annotation on a green run that nobody reads. US3's stated goal is unmet for those four
actions. `dependabot.yml`'s own comment asserts the opposite.

**The fix, in `4adc898`**: each entry now names the declined major **by version** — `download-artifact`
`["8.x"]`, `upload-artifact` `["7.x"]`, `checkout` `["6.x", "7.x"]`, `setup-node` `["7.x"]` — so the
decline does not generalize to the *next* major, which is the one a future runtime deprecation rides
in on. B1 stays closed: the majors this feature actually evaluated are still never re-proposed. The
file's comment block was rewritten to explain the distinction and to state the intended consequence
(when `checkout@v8` ships, Dependabot proposes it and the decision gets made again on current
information).

**Verified closed at 15:03**, and against upstream reality rather than the schema alone:
`gh api repos/<a>/git/matching-refs/tags/v` confirms `checkout`, `setup-node`, and `upload-artifact`
top out at v7 and `download-artifact` at v8, so every declined major is named and none is missed —
and `pnpm/action-setup` (≤ v6) and `softprops/action-gh-release` (≤ v3) have nothing above their
pins, which is why they correctly carry no entry. US3 is restored for all six bumped actions.

**The residual risk is narrow and lands on T017** (finding E4). GitHub's Dependabot reference
documents `versions:` as taking "the standard pattern for the package manager" and does not publish
the accepted syntax for the `github-actions` ecosystem. `N.x` is the idiomatic form and the file
passes a full key-level schema check, but acceptance is only observable once the file is on the
default branch. If the syntax is rejected the failure is **loud** — a config error on the repository's
Dependabot tab — not silent, and no workflow depends on it. Fallback shape if needed:
`versions: [">= 8.0.0", "< 9.0.0"]`.
