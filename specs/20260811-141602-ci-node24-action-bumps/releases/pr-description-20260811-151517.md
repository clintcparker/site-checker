## Summary

`ci.yml` and `release.yml` pinned every JavaScript GitHub Action to a major whose `runs.using` is `node20`, so both workflows emitted a Node 20 deprecation annotation on every otherwise-green run — the failure mode where nothing breaks and nobody looks. This change moves 14 `uses:` lines across six distinct actions to their lowest major that runs on `node24`, adds `.github/dependabot.yml` so the *next* runtime deprecation arrives as a pull request instead of as an annotation on a passing run, and records the resulting Actions-runner floor in a tracked how-to doc.

## Implementation

- **`.github/workflows/ci.yml` — 4 `uses:` lines bumped** across 3 distinct actions: `checkout` v4 → v5 (two call sites), `pnpm/action-setup` v4 → v6, `setup-node` v4 → v6.
- **`.github/workflows/release.yml` — 10 `uses:` lines bumped**: `checkout`, `setup-node`, `pnpm/action-setup`, `upload-artifact` v4 → v6, `download-artifact` v4 → v7, `softprops/action-gh-release` v2 → v3.
- **The rule is the lowest major that runs on `node24`, with two named exceptions.** `setup-node@v5` and `pnpm/action-setup@v5` are already `node24` and are still pinned a major higher: `setup-node@v6` narrows automatic caching to npm only, and all three call sites pass `cache: pnpm` explicitly, so the narrowing is never consulted; `action-setup@v6` only adds pnpm 11 and still self-updates to the `packageManager` version `package.json` pins. A first draft of the `ci.yml` comment block stated the rule without the exceptions, making it false about two of its own pins — QA failed it, and it was rewritten.
- **`download-artifact` stops at v7 deliberately.** v8 defaults `digest-mismatch` to `error`, turning a logged warning into a failed release run, and skips decompression. v7 still unzips and still defaults `merge-multiple: false`, so the `release` job's `artifacts/site-checker-<arch>/…` globs resolve unchanged.
- **`Swatinem/rust-cache@v2` and `dtolnay/rust-toolchain@stable` were left alone** — the first is already `node24`, the second is a composite action with no Node runtime.
- **`.github/dependabot.yml` is new**, scoped to `github-actions` at `/` on a weekly schedule, grouped, with an explicit open-PR limit. Cargo and npm are deliberately excluded — **not** because CI catches their drift (`cargo test --locked` and `pnpm install --frozen-lockfile` fail when a lockfile disagrees with its own *manifest*, and notice neither an upstream release nor a security advisory) but as a PR-volume choice for a single-user desktop app. Enabling security-only updates for those two ecosystems is recorded as an open decision, not made here.
- **`docs/how-to/release.md`** records the ≥ 2.327.1 Actions runner floor these pins imply, so a self-hosted runner is not introduced unknowingly. The repository has no self-hosted runners today (`actions/runners` → `total_count: 0`).

### Blocker B1 — how it was actually resolved

**Read this if you saw an earlier revision of this PR.** A prior body described the `ignore:` block as declining updates at `update-types: ["version-update:semver-major"]` — "the major line, not a version, so a later v8/v9 does not reopen a settled question." **That configuration no longer exists, and that reasoning was wrong.** The fifth staff review's blocker **D1** identified it: these actions are referenced by a *bare major tag*, so a major bump is the only update Dependabot can ever propose for them. Ignoring the major *line* would have silenced all four actions permanently — reinstating the exact failure `dependabot.yml` exists to prevent, and defeating US3.

Fixed in `4adc898`. Each entry now names the specific major this feature evaluated and declined, by version:

| Action | Declined | Next major still reachable |
|---|---|---|
| `actions/checkout` | `["6.x", "7.x"]` | v8 |
| `actions/setup-node` | `["7.x"]` | v8 |
| `actions/upload-artifact` | `["7.x"]` | v8 |
| `actions/download-artifact` | `["8.x"]` | v9 |

Verified against upstream rather than only against the schema: `gh api repos/<action>/git/matching-refs/tags/v` confirms `checkout`, `setup-node`, and `upload-artifact` top out at v7 and `download-artifact` at v8, so every declined major is named and none is missed. `pnpm/action-setup` (≤ v6) and `softprops/action-gh-release` (≤ v3) have nothing above their pins, which is why they correctly carry no entry.
