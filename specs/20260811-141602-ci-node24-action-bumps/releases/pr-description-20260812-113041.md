## The defect

The `github-actions` ecosystem parses `versions:` as a **Gem requirement**. RubyGems accepts `8.x` as a
legal *version* — it permits alphabetic segments, as in `1.0.beta` — so `versions: ["8.x"]` compiled to
the equality `= 8.x`, a match against a version that will never exist. It raised no error; it simply
matched nothing. The grammar was reproduced in Ruby rather than assumed:

| Input | Compiles to | Matches |
|---|---|---|
| `"8.x"` | `= 8.x` | nothing (`Gem::Version.correct?("8.x")` → `true`, which is *why* it was silent) |
| `"8"` | `= 8` | `8`, `8.0.0` — the bare major tag Dependabot reports |
| `"7.*"` | — | raises `Gem::Requirement::BadRequirementError` (would have been loud) |

All four entries are now bare integers. `>= 8` also parses but declines every future major forever —
the permanent-silence failure that blocker D1 was raised against two reviews ago, and the reason the
narrow per-version form exists.

**The fix is now backed by production evidence, not only by a local REPL.** PR #28's own
`updated-dependencies` commit trailer emits `dependency-version: '8'` for `download-artifact` and
`'7'` for `checkout`, `setup-node`, and `upload-artifact` — bare integers, which is exactly what the
corrected `= 7` / `= 8` requirements match. The corrected entry is an exact match against the string
Dependabot actually produced for the very upgrade the broken entry failed to decline.
