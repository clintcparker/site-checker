## Executive Summary

**D1 is fixed and the fix is verified. Zero blockers. The two conditions are that `release.yml` is
still inspection-only, and that T017 now carries weight it did not carry before.**

`.github/dependabot.yml`'s `ignore:` block no longer declines the `semver-major` *line* for
`actions/checkout`, `actions/setup-node`, `actions/upload-artifact`, and
`actions/download-artifact`. Each entry now names the specific major this feature evaluated and
declined — `checkout` `["6.x", "7.x"]`, `setup-node` `["7.x"]`, `upload-artifact` `["7.x"]`,
`download-artifact` `["8.x"]` — so the *next* major above each is still proposed. That is the one
that matters: a Node runtime deprecation ships as a major, and the previous form had pre-emptively
agreed never to mention it. US3 is restored for all six bumped actions, and B1 stays closed —
nothing this feature declined can be re-proposed.

The fix was checked against upstream reality, not just against the schema. `gh api
repos/<a>/git/matching-refs/tags/v` confirms `checkout`, `setup-node`, and `upload-artifact` top out
at v7 and `download-artifact` at v8, so every declined major is named and none is missed; and
`pnpm/action-setup` (≤ v6) and `softprops/action-gh-release` (≤ v3) have nothing above their pins,
which is why they correctly carry no entry.

**US1 is confirmed on a live runner at the fixed head.** CI run
[31540635351](https://github.com/clintcparker/site-checker/actions/runs/31540635351) at `4adc898`
concluded `success` on both jobs, and `check-runs/93941992233/annotations` and
`check-runs/93941992315/annotations` both return `[]`. That is now the fifth consecutive
annotation-free run on this branch. All four constitution code gates are green: 62 Rust tests,
47 frontend tests, clippy clean, `actionlint` exit 0. 20 `uses:` lines, zero `@v4`.

Two documentation defects were fixed alongside the blocker. `CHANGELOG.md` had kept the exact false
claim W1 removed from `dependabot.yml` — that `--locked`/`--frozen-lockfile` catch upstream cargo/npm
drift. It now says plainly that they do not, gives the real reason for the exclusion, and names the
security-update consequence. Its closing paragraph no longer says the change was verified "not
against a live runner"; that caveat is narrowed to `release.yml`, where it is still true.

**The residual risk worth naming is narrow and it lands on T017.** GitHub's Dependabot reference
documents `versions:` as taking "the standard pattern for the package manager" and does not publish
the exact syntax for the `github-actions` ecosystem. `N.x` is the idiomatic form — 2,124 public
`dependabot.yml` files pair `github-actions` with a `versions:` list — and the config parses and
passes a full key-level schema check. But whether Dependabot *accepts* these ranges is only
observable once the file is on the default branch. If it does not, the failure is loud (a config
error on the repository's Dependabot tab) rather than silent, which is the right way round. **T017
is no longer a formality.**
