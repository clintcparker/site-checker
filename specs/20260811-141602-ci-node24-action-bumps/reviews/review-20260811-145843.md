## Executive Summary

**The pins are right, US1 is confirmed on a live runner at the current head, and every constitution
gate is green. One blocker: the fix that closed B1 defeats User Story 3 for four of the six actions
this feature just bumped.**

`.github/dependabot.yml`'s `ignore:` block declines `actions/checkout`, `actions/setup-node`,
`actions/upload-artifact`, and `actions/download-artifact` at
`update-types: ["version-update:semver-major"]` — the major *line*, not a version. All four are
referenced by a bare major tag (`@v5`, `@v6`, `@v6`, `@v7`), and for an action referenced that way
the only version update Dependabot can propose is a major bump. So the ignore is not narrow, it is
**total**: Dependabot will never open a version-update PR for any of those four actions again.

That is the exact failure this feature exists to prevent, reinstated for 11 of the 14 `uses:` lines
it bumped. When GitHub retires Node 24 the way it retired Node 20, `checkout@v8` (or whatever
carries the next runtime) is a major, it is ignored, and the deprecation arrives as an annotation
on a green run that nobody reads. `dependabot.yml:38–43` asserts the opposite in its own comment:
*"ignoring these costs nothing in runtime currency, which is the only thing this file exists to
track."* It costs precisely that, and only that.

The fix is small and keeps B1 closed: decline the **specific majors this feature evaluated** with
`versions:` rather than the whole major line. `download-artifact` declined v8, `upload-artifact`
declined v7, `checkout` declined v6 and v7, `setup-node` declined v7 — all verified to exist
upstream. Naming those leaves the *next* major live, which is the one that matters.

Everything else in this branch holds up. CI run
[31539766422](https://github.com/clintcparker/site-checker/actions/runs/31539766422) at `9eb0cc6` —
the current head, not the older SHA the prior review and the PR body cite — concluded `success` on
both jobs with `check-runs/93939274988/annotations` and `check-runs/93939275131/annotations` both
returning `[]`. T007 is satisfied at the tip, not just at `bed16c1`. 62 Rust tests, 47 frontend
tests, clippy clean, `actionlint` exit 0, 20 `uses:` lines, zero `@v4`.

Two warnings are about the record rather than the pins. **`CHANGELOG.md` still carries the exact
false claim that W1 removed from `dependabot.yml`** — it says cargo and npm are excluded because
`--locked`/`--frozen-lockfile` "hard-error on lockfile drift", which the config file now explicitly
denies. The fix landed in one file and missed the other, and the CHANGELOG is the copy that
outlives the branch. And **PR #27's links to the current review 404**: they pin `f5032b6`, where
`review-20260811-144605.md` does not exist and where `tasks.md` still shows T007 unchecked —
contradicting the body's own table entry claiming it was checked off.

## Why D1 is a blocker and not a warning

It is worth stating plainly, because the previous review graded the same block as a *fix*.

1. **It removes the feature's only preventive control.** US1 and US2 are corrective — they retire a
   warning that exists today. US3 is the only thing standing between this repo and the identical
   warning in two years. For `checkout`, `setup-node`, `upload-artifact`, and `download-artifact`,
   it now does nothing.
2. **It fails silently and permanently.** An ignored dependency produces no PR, no annotation, and
   no entry anywhere a maintainer looks. This is the same class of invisible decay the feature was
   opened to fix — that is the point of the finding, not a rhetorical flourish.
3. **The file documents itself as doing the opposite.** `dependabot.yml:41–43` says ignoring these
   *"costs nothing in runtime currency, which is the only thing this file exists to track."* A
   future maintainer reading that has no reason to re-derive the consequence.
4. **The cheaper alternative was available and preserves B1's fix.** `versions:` declines the
   evaluated majors without generalizing. There is no tradeoff being made here — the broad form was
   chosen for a benefit (*"a later v8/v9 does not reopen a settled question"*) that is precisely the
   harm.

The mechanism was verified rather than assumed: GitHub's own `ignore` reference confirms
`update-types` filters by SemVer tier, and a search of public PRs confirms that a major-tag action
reference produces `Bump actions/checkout from 4 to 5` — a major update — as its only version-update
shape. Both checks are recorded in the table below.
