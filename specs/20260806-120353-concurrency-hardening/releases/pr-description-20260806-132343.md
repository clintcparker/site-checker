## Summary

Closes the three actionable items in `docs/ROADMAP.md` §1 ("Concurrency & robustness hardening"). All three are latent correctness holes in the Rust layer beneath the UI — reachable by a future caller, an importer, or a restore path, but not by a user clicking around in the shipped window today. The value is that the core stops relying on the window to avoid states it permits.

The headline is fault recovery: today a single panic inside any critical section poisons that lock and cascades a panic into every later command, so the window keeps ticking status updates while refusing to add, edit, delete, or even list anything until the app is relaunched. After this change, one internal fault costs at most the operation it happened in.

Zero frontend files change. No dependency is added, runtime or dev. Nothing about `sites.json` — shape, field names, or location — moves.

Three user stories, eighteen functional requirements:

- **US1 (P1) — The app stays usable after an internal fault.** FR-001…FR-007. Every access to the shared site list, the check registry, and the startup warning must keep working after a prior fault. Recovery preserves whatever the interrupted operation left behind; it must not reset the list or restart checks. A site-list recovery warns the user through the existing banner; a check-registry recovery is silent. Absent any fault, every operation behaves exactly as it does today.
- **US2 (P2) — A refused add never leaves a ghost row.** FR-008…FR-012. A duplicate-id refusal must be distinguishable from a failed disk write. A refusal adds no row, starts no checks, leaves both the in-memory list and the file untouched, and is reported in terms that do not imply the change is merely un-saved. A genuine write failure keeps today's behaviour exactly.
- **US3 (P3) — Two edits to one site cannot discard each other.** FR-013, FR-014. An edit must read current state and write its result as one indivisible step, with the rules deciding an edited entry's contents unchanged.
- **Scope guards.** FR-015…FR-018: no on-disk change, no new user-facing capability (only two user-visible message changes permitted), every behaviour pinned by a test that fails against today's code, and the symlink-replacement behaviour explicitly left alone.

## Implementation

Four Rust files changed (`lib.rs`, `commands.rs`, `engine.rs`, `store.rs`), one added (`lock.rs`). No frontend file touched.

**Fault recovery (US1).** Ten `Mutex::lock().unwrap()` call sites were not fixed ten times over. `SharedStore` now wraps `Arc<Mutex<Store>>` and exposes no accessor for the raw mutex, so a store lock *cannot* be taken un-recovered — the guarantee is structural rather than a call-site convention. Recovery is `PoisonError::into_inner()` (preserves the interrupted operation's leftovers, FR-006) plus `Mutex::clear_poison()` (makes the poison one-shot, so the user gets one banner per fault rather than one per subsequent action). The two task-registry locks and the startup-warning lock call the same `lock::recover` helper directly and discard its flag: recovering them is required, warning about them is not, because the check registry is ephemeral by design and rebuilt every launch.

**Refused add (US2).** A two-variant `AddError` lets `add_site` branch instead of funnelling every `Store::add` error into `warn_on_write_failure` and returning `Ok`. Refusal returns `Err` — no row, no timer, no banner. Write failure keeps today's path verbatim.

**Atomic edit (US3).** The read-decide-write moved out of `update_site` and into `Store::replace`, where a single `&mut self` borrow makes the interleaving impossible by construction. Collapsing that double acquisition is why the lock-site count goes 10 → 9. It also moves the `method_override` decision rule out of the untested `commands.rs` into the temp-dir-tested `store.rs`.

**Contract preserved.** `AddError`, `Replaced`, and `SharedStore` are internal Rust types that never cross the IPC boundary; the commands map them to the existing `Result<Site, String>` / `Result<(), String>` shapes, so the frontend contract is byte-identical. Poison recovery is `std::sync` only — `tauri`'s `test` feature was considered and declined (research R7).
