## QA Summary

Every acceptance criterion this feature names was exercised, and none failed. All five automated
gates are green (`pnpm test` 98/98, `tsc --noEmit`, `cargo test` 101/101, `clippy -D warnings`,
`pnpm build`), and the design assertion that makes the feature cheap holds exactly:
`git diff origin/main...HEAD -- src-tauri/` is empty and the three CI-enforced version sentinels
are untouched. The About surface was then driven interactively in a real renderer against the
shipped `src/about.ts`, `src/open.ts`, `index.html` and `src/styles.css` — the dialog opens from a
visible footer control, reads `Site Checker` / `Version <verbatim>` / `Created by Clint Parker`,
carries `data-open-url="https://clintparker.com"` on a `<button>` (no `href`, no `target`, so the
page is never navigated), collapses ten activations inside one second into exactly one open, and on
a refusal closes itself *before* writing a plain-language message to the banner — 37 ms, against
SC-005's one-second bound.

The verdict is PARTIAL rather than ALL PASSED for one reason, and it is an evidence gap rather
than a defect: **the Mac's screen is locked** (`CGSSessionScreenIsLocked: true`, verified this
run), so the shipped Tauri window could not be shown, driven, or captured. Four checks assert
things only the native app can show — that a real browser actually comes forward (M3, M4's browser
half, M7), and that the dialog fits the app's 480×320 *window* rather than a 480×320 *browser
viewport* (M6/FR-012). These are the same two open items the staff review raised as W1 and W2;
this run closes neither, and reproduces the same wall the screenshots before-pass hit. Every
DOM-level assertion behind them was performed and passed.

Two of the staff review's suggestions were reproduced as live behaviour rather than left as code
reading: focus lands on the link when the dialog opens, so Enter immediately leaves the app (S2),
and a failed version read never retries for the life of the process (S3). Neither violates a
requirement; both are recorded below.

## Failure Details

**No failures.** Nothing regressed and no scenario produced a wrong result. The items below are
the evidence gap behind the PARTIAL verdict, and two confirmed non-blocking observations.

### TC-017: Real browser comes forward (M3, M4 browser half, M7)

**Status**: 🔵 BLOCKED — environment, not automation
**Expected**: activating the link brings the default browser forward at clintparker.com on the
first attempt, with no intermediate dialog (SC-003); ten rapid clicks yield one new tab (M4);
offline, the browser reports its own failure while Site Checker shows nothing (M7).
**Actual**: not observed. The Mac's screen is locked (`CGSSessionScreenIsLocked: true`, probed
this run via `ioreg -n Root -d1 -a`), so the shipped Tauri window cannot be shown, driven through
the accessibility API, or captured — `screencapture -R` fails and a full-screen grab would yield
only the lock screen.
**What was proven instead**: the frontend calls `openUrl` exactly once with the exact address, and
`open_url`'s scheme guard `openable_url` accepts `https://clintparker.com` under `cargo test`. The
untested link in the chain is `/usr/bin/open` → LaunchServices, which this feature does not touch.
**Severity**: Low — residual risk is small and the path is pre-existing and shipped, but "low" is
not "checked".

### TC-010 / FR-012: minimum size measured in the wrong renderer

**Status**: ⚠️ PARTIAL
**Expected**: readable and activatable at the app's 480×320 *window* minimum.
**Actual**: verified at a 480×320 *Chromium viewport*. The dialog occupies 320×188 with 132 px of
vertical headroom, and `max-height: calc(100vh - 48px)` with `overflow-y: auto` degrades to a
scroll rather than a clip — so the margin comfortably absorbs the ~28 px a native title bar takes.
Very likely fine; not the thing the requirement names.
**Severity**: Low.

impossible because the screen was locked, and the same Vite + Playwright fallback was used. That
condition still holds, so this run and the before pass are like-for-like.
