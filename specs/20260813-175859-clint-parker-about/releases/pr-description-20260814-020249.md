## Known issues

Both the review and the QA report were remediated once and still carry non-passing verdicts. Every
surviving finding is below. **None is a defect** — the two warnings are the same evidence gap, and
neither closes without an unlocked screen.

### Warnings — accepted unverified

- **W1 — the real-browser half of FR-006 / SC-003 was never observed.** The Mac's screen was locked
  for the whole implementation, screenshot, review and QA runs (`CGSSessionScreenIsLocked: true`,
  probed each run), so the shipped Tauri window could not be launched, driven, or captured. Manual
  checks **M3, M4's browser half, and M7 are unrun**. What *was* proven: the frontend calls `openUrl`
  exactly once with the exact address, and `open_url`'s `openable_url` scheme guard accepts
  `https://clintparker.com` byte-identically under `cargo test`. The untested link in the chain is
  `/usr/bin/open` → LaunchServices, which this feature does not touch. Residual risk is low; low is
  not checked.
- **W2 — FR-012 was verified in the wrong renderer.** The dialog was measured at 320×188 inside a
  480×320 *Chromium viewport*, not the app's WKWebView at its 480×320 *window* minimum. Native
  title-bar chrome consumes vertical space a browser viewport does not. The margin is large — 132 px
  of headroom, and `max-height: calc(100vh - 48px)` with `overflow-y: auto` degrades to a scroll
  rather than a clip — so this is very likely fine, but it is not what the requirement names.

Both close in a single `pnpm tauri dev` session on an unlocked screen, in about two minutes. Also
outstanding there: **M6** (native minimum size), **M8** (forced-failure rebuild) and **M9** (real-app
config-hash session).

### Suggestions — carried forward, not silently dropped

- **S1 — contract drift.** `contracts/about-surface.md` §2 still reads "fetches the version, then
  `showModal()`"; the implementation deliberately reverses this. The observable contract is unchanged,
  but the document now describes an order the code does not use. Cheapest item here.
- **S2 — `showModal()` focuses the link, not the dismissal.** Confirmed live by QA: pressing Enter
  right after opening About immediately calls `openUrl` and leaves the app. No requirement is
  violated (SC-003 concerns deliberate activation), but the dialog's default action is currently
  "leave", not "dismiss". One attribute fixes it: `autofocus` on `[data-about-close]`.
- **S3 — a failed version read never retries.** `versionRequested` latches on first open regardless
  of outcome, pinning the line at "Version unavailable" for the process's life. Confirmed live
  (`fetchAttempts: 1` after reopening). The value is a build constant, so a transient failure is close
  to hypothetical.
- **S4 — `src/main.test.ts` hand-restates markup that `about.test.ts` deliberately refuses to
  restate.** `about.test.ts` reads the shipped `index.html` via `?raw` precisely so a fixture cannot
  agree with itself; the wiring stub reintroduces a hand-typed copy. Exposure is small — its
  assertions only prove wiring — but a rename of `#about` would leave it green against markup that no
  longer ships.
- **S5 — no action required.** `mountAbout` runs after `await listSites()`, so an earlier rejection
  would leave `#about-open` visible but inert. This is the *existing* exposure of `mountForm` and
  `mountUrlOpener`; recorded so the consistency is a deliberate choice rather than an unnoticed one.

### Test coverage gaps (minor)

The "markup missing" bail-out in `about.ts:35-38` is uncovered (three lines), and `getVersion` is
mocked everywhere, so the real IPC path is never exercised — the capability grant was confirmed from
the generated `macOS-schema.json` instead, but a permission regression would surface only at runtime.
